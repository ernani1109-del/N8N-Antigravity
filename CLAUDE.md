# CLAUDE.md

Guidance for AI assistants (and humans) working in this repository.

## Project status

This repository was just scaffolded (2026-07-02) as a minimal Node.js/TypeScript
starter. There is no application logic yet beyond a placeholder `greet`
function — treat everything here as the baseline to build on, not a mature
codebase with established patterns. Update this file as real structure and
conventions emerge.

## Stack

- **Runtime**: Node.js (v22+), ESM (`"type": "module"` in `package.json`)
- **Language**: TypeScript, `strict` mode, compiled with `tsc`
- **Test runner**: Vitest
- **Lint**: ESLint 9 flat config (`eslint.config.js`) with `typescript-eslint`
- **Formatter**: Prettier
- **Dev runner**: `tsx watch` for live reload

## Repository structure

```
src/
  index.ts              # entry point / library exports
  __tests__/            # Vitest tests, colocated under src
dist/                   # compiled output (gitignored, generated by `tsc`)
tsconfig.json           # NodeNext module resolution, strict mode
eslint.config.js        # flat ESLint config
package.json
```

Tests live in `src/__tests__/` next to the code they cover, named
`*.test.ts`. Follow this convention for new modules
(e.g. `src/foo.ts` → `src/__tests__/foo.test.ts`).

## Commands

| Command | Purpose |
|---|---|
| `npm install` | Install dependencies |
| `npm run dev` | Run `src/index.ts` with live reload (`tsx watch`) |
| `npm run build` | Type-check and compile to `dist/` |
| `npm start` | Run the compiled output from `dist/` |
| `npm test` | Run the Vitest suite once |

| `npm run format` | Format the repo with Prettier |

Run `npm run build`, `npm test`, and `npm run lint` before considering a
change complete — there is no CI configured yet, so this is the only
verification available.

## Conventions

- **ESM only**: use `import`/`export`, not `require`/`module.exports`. When
  checking for a module's "is this the entry point" condition, compare
  `import.meta.url` against `process.argv[1]` (see `src/index.ts`), not
  `require.main`.
- **Module resolution**: `tsconfig.json` uses `NodeNext` — relative imports
  between TypeScript files must include the `.js` extension (e.g.
  `import { greet } from '../index.js'`), even though the source file is
  `.ts`. This is required by NodeNext resolution, not a typo.
- **Strict TypeScript**: `strict: true` is on. Avoid `any`; prefer explicit
  types on exported function signatures.
- No global state or config files beyond what's listed above yet — don't
  invent framework-specific structure (routes, controllers, etc.) unless the
  project actually grows in that direction.

## Working on this repo

- Prefer adding small, focused modules under `src/` with a colocated test in
  `src/__tests__/` over growing `index.ts` into a catch-all file.
- Keep `package.json` scripts as the single source of truth for how to
  build/test/lint/run the project — don't introduce a separate Makefile or
  task runner without reason.
- If you add real dependencies (frameworks, HTTP clients, etc.), update the
  "Stack" section above so this file stays accurate.

## Superpowers skills (vendored)

This repo vendors the [Superpowers](https://github.com/obra/superpowers) skill
library under `.claude/` so the skills travel with the project instead of
requiring a global plugin install:

```
.claude/
  skills/          # 14 skills (TDD, systematic-debugging, brainstorming, …)
  hooks/           # session-start hook + cross-platform run-hook.cmd wrapper
  settings.json    # registers the SessionStart hook
```

- The `SessionStart` hook in `.claude/settings.json` injects the
  `using-superpowers` skill at the start of each session; the other skills load
  on demand via the `Skill` tool. Together they make the skills activate
  automatically — no special command needed.
- The vendored `session-start` hook was adapted to emit Claude Code's
  `hookSpecificOutput` format when run as a project hook (it keys off
  `CLAUDE_PROJECT_DIR`, since a repo-local hook has no `CLAUDE_PLUGIN_ROOT`).
- To update, re-vendor from upstream (`obra/superpowers`, `skills/` and
  `hooks/`) rather than editing skill files in place.
- Antigravity users can alternatively install upstream directly with
  `agy plugin install https://github.com/obra/superpowers`.
